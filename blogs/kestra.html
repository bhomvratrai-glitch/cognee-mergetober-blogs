Kestra Orchestration Platform Connector: Automated Pipeline Diagnostics

By Bhomvrat Rai (@bhomvratrai-glitch) • Issue #6171

1. The Problem: Operational Knowledge Trapped in Logs

Kestra is an open-source orchestration platform managing hundreds of mission-critical ETL jobs and microservice workflows. When scheduled runs fail at 3 AM, debugging context is typically scattered across YAML specifications, execution run-states, and failure logs.

2. Architecture: Connecting Flow Topologies and Error Telemetry

Implemented under packages/connector/kestra/, our connector bridges Kestra's operational state into Cognee's cognitive graph:

Technical Capabilities:
• Flow Topology Ingestion: Ingests task definitions, triggers, schedules, and namespace metadata.
• Execution & Error Capture: Tracks execution runtimes, task statuses, and captures specific warning/error logs.
• Root-Cause Reasoning: Empowers Cognee agents to answer complex questions like "Why did the nightly ingest flow fail last week and has this timeout occurred before?"
• Hermetic Testing: 3/3 passing unit tests completely offline in 0.56s.

3. Quickstart Code

import asyncio
import os
import cognee
from cognee_community_connector_kestra import kestra_source

async def main():
    source = kestra_source(
        base_url=os.getenv("KESTRA_BASE_URL", "http://localhost:8080"),
        namespaces=["prod", "etl"],
        include_logs=True,
    )
    await cognee.add(source)
    await cognee.cognify()

    results = await cognee.search("Why did the nightly ingest flow fail last week?")
    for res in results:
        print("-", res)

if __name__ == "__main__":
    asyncio.run(main())
